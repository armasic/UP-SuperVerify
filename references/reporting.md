# 正式验证交付

## 正文结构

报告面向其他工程师或验收者，采用简洁正文与完整明细附件。标题明确项目、用途和版本，开头直接给结论与适用范围。表格用于可比较的记录，长说明用短段落；不按固定页数删减测试。

1. **验证策略**说明范围、关键风险、独立判据和选择测试方法的理由。针对适用的复位、协议、异常、并发、吞吐和延迟，给出覆盖与退出条件。
2. **验证方案**把 LRS ID 映射到用例、变体和检查点，写出前置条件、刺激次序、采样边沿、预期，以及如何发现典型缺陷。列出要留原始波形的关键检查点。
3. **验证结果**对照同一批 ID 写当前基线的实测、结论及证据。放入关键用例的实测波形、工具及配置、修复回归、覆盖分母、豁免和缺口。正文开头可先概述验收结论。

版本、签署和修订信息按交付方实际要求提供，不机械制造多页空表。正式文件不带对话过程、生成过程说明、助手自评分或“请您确认”等聊天残留。重要状态和限制属于报告本身，不能为了精炼删除。

## 实测波形

核对波形所属的仿真批次后，复用其 VCD 或 FSDB。Verdi 可用时，默认用 nWave 的 `wvCapture` 截取白底 PNG，配深色信号线和文字。项目指定其他查看器或环境缺少 Verdi 时，用项目可用的查看器从同批波形导出，并注明实际工具。

批量出图时优先复用 Tcl 和窗口清单。逐图记录用例、信号层级、时间单位、起止时间和游标位置。批处理启动 Verdi 时，用 `-rcFile` 和 `NOVAS_GUICONF` 指向任务目录里的独立显示配置，出图后关闭本次会话。

使用已有的 Python 核对脚本或其他独立读数方式，从原始波形复核截图中的关键边沿及其前后值。保留原始波形、导出入口和窗口清单。图注给出 LRS、用例/变体、检查点、仿真批次、采样时刻、预期与实测。插入 Word 后核对信号名、时标和值是否可读。示意时序图用于讲解设计。计划要求的实测波形缺失时，在报告中逐项标明。

## 明细与去重

完整验证表至少保存需求/case/变体/CP ID、来源引用、公共配置引用与本例差异、具体刺激顺序、对象、采样窗口、预期、实现入口、实际运行与观察、结果及证据。各 CP 独立判断；一个大段“响应/数据/状态均正确”不可替代明细。

公共初始化和同族步骤写一次；变体保留所有独立差异。将重复的限制集中编号，局部引用，正文保留会影响验收的项目。日志、波形与数据库放证据附件，以编号定位，不逐段粘贴。完整用例表不在索引、正文小节和表题里反复复制。

验证方案说明预定检查，验证报告说明实际检查与结果；二者可由同一台账生成，但不得因方案有预期就填“通过”。结果表不得用用户输入的摘要覆盖实际评价。通过率不改称覆盖率；没有覆盖采集或对应报告时写未采集/证据不足。其他批次的数值保留其来源，不混入本次统计。

## 文件与工具

正式模块四文档沿用同版可用的模板，保留已测量的数值、原图、证据定位与项目已确认的内容。更换版式时核对来源与表格，不移植范例中的信号、结果、版本或签署信息。没有模板时，按以下版式生成。

- Word 采用 A4，页边距按上、左、下、右分别为 1644、1418、1418、1134 twips（约 29、25、25、20 mm）。封面列出项目、模块、文件名称、文件编号、文件版本号、项目任务号和编制日期。未分配的编号留空，编制日期填写实际日期，修订记录保留历史。封面无页码，前置修订、目录、图目录和表目录使用大写罗马数字 I、II。章节目录在前；另起一页先列表目录、再列图目录，前置罗马页码连续。没有相应图表时省去对应目录。前置和正文右页眉标识模块；正文右页脚从“第 1 页 共 N 页”独立起算，N 取正文末页。
- 中文正文用宋体，西文用 Times New Roman，多级标题用黑体。工程表采用黑字与黑线，跨页重复表头。图表按章节独立编号，例如“表 2-1”“图 3-2”。表题在表上，图题随实测图，目录页码与实际页对应。白底波形在最终纸页上应能读清信号名、单位、采样游标与数值。长窗口可以分图，保留完整原始证据。
- LRS 工作簿保留单独的版本记录、稳定条目 ID 及分类、术语、决策和验收追溯。表头用绿色 `#A9CE91`，辅助区用浅蓝色 `#D9E2F3`，采用等线并冻结数据表首行。项目/要求/测试/结果使用同一组 ID。按项目实际内容填写，核对原有数值、条件和未决项。已有 LRS 时审阅并沿用交付权限内的版本。
- 文件名、封面、LRS 当前版本页、当前修订、验证计划、明细及 `latest/` 都须对应同一正式版本。例如旧模板 V0.5 对应本次数字 0.5 时，交付标识写作 `v0p5`。同书名 PDF 从最终 Word 导出。外部协议版本和历史修订仍保留原义。

## 导出与排版校核

机器契约见[数据契约](data-contract.md)。通用无 `module_report` 的 Word/Markdown 与模块 Markdown 都是简报，可用于阶段交流。以下正式模块入口使用 `python-docx` 创作可编辑 Word，使用宿主已提供的 LibreOffice 和 `pypdf` 回填并验证页码。先按宿主提供的方式解析依赖，命令中的目录、版本与可执行文件换成当前项目的实际值。

```sh
python3 scripts/render_report.py --root MODULE --plan verification/plan.json \
  --results verification/results.json --output MODULE/docs/验证文档_v0p1.docx \
  --soffice /path/to/soffice --pdf
python3 scripts/verify_layout.py MODULE/docs/验证文档_v0p1.docx
```

输出的 `验证文档_v0p1.docx`、`验证文档_v0p1.pdf` 和 `验证文档-details_v0p1.csv` 采用同一次证据评价。省略 `--pdf` 时仍执行排版渲染，可仅交付 Word。省略 `--soffice` 时得到带 Word 域的候选稿，状态为 `CANDIDATE`，随后可用同一冻结台账重复上述导出。已分配文件编号、任务号或已有编制日期时，用 --document-number、--task-number、--issue-date YYYY-MM-DD 填入。需要沿用人工编辑的同版模板时，在副本中更新图表与交叉引用。使用 Word 或 LibreOffice 刷新域，另存同书名 PDF，将实际页码、标题、题注和证据链接逐项与定稿核对。

打开排版结果逐页查看封面身份、前置及正文页码、目录与正文落点、跨页表头、长文本、波形文字和图表题注。抽查真实相对链接，可定位至本次计划、逐项明细、截图和原始波形；归档路径和 latest/ 相邻时，证据通过共同的模块目录定位。从发布包内的归档目录和 latest/ 分别运行 verify_layout.py，并验证链接。没有渲染能力时记录具体未核项目，交付候选稿及可复核证据。如渲染后出现方框或空白，为当前渲染进程配置支持中文的可用字体后重渲染。

## 最终核对

读者应能快速回答：验证了哪个版本、哪些要求、实际结果如何、修复了什么、什么尚未验证、怎样复现。正文结论与附件数据一致，引用可打开，证据来自最终交付输入。对外材料不包含凭据、许可值、私有绝对机器路径或不必要的内部日志。
